FASE 3 — AUDITORÍA COMPLETA

1. Arquitectura: Analizar separación de responsabilidades, componentes demasiado grandes, duplicación, acoplamiento, reutilización, modularidad, Clean Architecture, SOLID, DRY, KISS. Detectar oportunidades de simplificación.
2. package.json: Revisar dependencias obsoletas, duplicadas, innecesarias, versiones incompatibles, librerías abandonadas. Antes de proponer nuevas librerías, demostrar que las actuales no resuelven el problema.
3. React: Buscar renders innecesarios, re-render masivo, memoización faltante (React.memo, useMemo, useCallback), lazy loading, Suspense, code splitting, contextos demasiado grandes, estado innecesario, prop drilling, hydration issues, Layout Shift. 
🚨 ALERTA CRÍTICA: Verifica obsesivamente que los `useEffect` que contienen llamadas a Firestore NO tengan dependencias inestables que causen loops infinitos de lectura/escritura (Riesgo de facturación masiva).
4. TypeScript: Buscar any, casts inseguros, tipos duplicados, interfaces repetidas, null no controlado, undefined, errores silenciosos, tipado débil.
5. Firestore: Buscar consultas O(N), Full Collection Scan, lecturas duplicadas, listeners innecesarios, consultas repetidas, consultas sin índices, subcolecciones mal utilizadas, documentos demasiado grandes, campos innecesarios, consultas sin paginación, costos evitables. Proponer índices compuestos cuando sea necesario.
6. Cloud Functions: Buscar duplicación, timeouts, llamadas repetidas, errores no controlados, logs innecesarios, manejo de errores, validaciones, reintentos, cold starts.
7. Seguridad: Auditar completamente Authentication, Firestore Rules, Storage Rules, Cloud Functions, Variables de entorno, Secrets, App Check, Custom Claims, Escalada de privilegios, Validación Backend/Frontend, email_verified, rate limiting, input validation, sanitización, inyecciones, XSS, CSRF.
8. Matemáticas: Revisar absolutamente todas las fórmulas. Especialmente: totales, subtotales, IVA, impuestos, descuentos, porcentajes, redondeos, acumulaciones, decimales, overflow, underflow, precisión, divisiones, conversiones. Nunca asumir que una fórmula es correcta.
9. Estado: Buscar race conditions, promesas sin await, estados inconsistentes, actualizaciones perdidas, doble ejecución, asincronía incorrecta, cancelación de peticiones, memory leaks.
10. UI: Optimizar Layout Shift, espaciados, alineaciones, feedback visual, animaciones, loading, skeletons, placeholders, errores, vacíos, responsive, accesibilidad, ARIA, contraste, teclado, focus.
11. Audio: NO añadir sonidos porque sí. Solo proponer microinteracciones sonoras cuando mejoren UX, sean discretas, opcionales, puedan desactivarse y no afecten rendimiento. Priorizar librerías ligeras.
12. Rendimiento: Analizar bundle, tree shaking, lazy loading, imágenes, cache, memoización, virtualización, CPU, RAM, Network, Core Web Vitals, Lighthouse.
13. Documentación: Verificar que toda documentación refleje exactamente el código existente. Actualizar README, manuales, diagramas, comentarios y AUDIT_NOTEBOOK.
